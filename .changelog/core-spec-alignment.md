github.com/tempoxyz/mpp-go: minor

Aligned servers and clients with the core and Tempo charge specifications: replays now get 402 invalid-challenge with a fresh Challenge, Challenges carry a 16-byte `_mpp_nonce` (`_mppx_nonce` still verifies), credentials are checked in the specified order with multiple credentials rejected as 400 and unselected or bare ones ignored, and `VerifyOrChallenge` refuses secrets under 32 bytes. Tempo servers enforce a new `methodDetails.memo` (`ChargeParams.Memo`) on the primary transfer; without it, push (hash) payments must still carry the Challenge's attribution memo, while pull (transaction) payments may carry it, another memo or none, but never this realm's attribution memo for another Challenge. An `OnChallenge` hook returning `client.ErrPaymentDeclined` before the method runs now returns the 402 without paying. The HTTP and MCP clients no longer pay a fresh Challenge that answers a sent Credential with invalid-challenge: the MCP client returns a `ReconciliationError` holding the sent Credential.
